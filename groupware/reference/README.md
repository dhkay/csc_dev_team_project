# reference

개발할 때 사람이 열어보는 참고 자료를 두는 자리다. 실행되지 않고 빌드에도 들어가지 않는다.

```
reference/
├── README.md      커밋
├── data/          csv, xlsx, json 등 샘플 데이터 (커밋)
├── images/        스크린샷, 디자인 시안, 참고 화면 (커밋)
└── local/         대용량 원본, 고객 제공 파일, 민감 자료 (gitignore, 로컬 전용)
```

하위 폴더는 필요할 때 늘린다(예: `pdf/`, `fonts/`). 새로 만든 폴더도 아래 규칙을 그대로 따른다.

## 여기 두는 것과 두지 않는 것

| 자료 | 자리 |
|------|------|
| 화면을 만들 때 보고 옮기는 시안, 스크린샷 | `reference/images/` |
| 스키마 설계나 파싱 규칙을 확인할 샘플 csv | `reference/data/` |
| 고객이 준 원본 엑셀, 수십 MB 짜리 수집 덤프 | `reference/local/` |
| 앱이 런타임에 서빙하는 정적 파일 | `apps/<앱>/static/` |
| 사용자가 업로드한 파일 | `Storage/{env}/` (file-upload 가 관리) |
| 규칙과 계약을 적은 문서 | `docs/` |
| 개인 실험 코드 | `sandbox/` |

구분 기준은 하나다. **이 폴더의 파일은 코드가 읽지 않는다.** 테스트가 읽어야 하는 고정 입력은
fixture 이므로 그 테스트 옆에 둔다. 앱이 읽어야 하는 데이터는 `static/` 이나 DB 로 간다.
`reference/` 에는 사람이 눈으로 보는 자료만 둔다.

## 커밋 규칙

`data/` 와 `images/` 는 커밋한다. 팀원이 같은 자료를 보고 작업해야 하기 때문이다.
`local/` 은 `.gitignore` 가 내용을 전부 무시한다(폴더 자체는 `.gitkeep` 으로 남긴다).

`local/` 로 보내는 기준 셋:

1. **파일 하나가 수 MB 를 넘는다.** git 은 한 번 커밋한 바이너리를 히스토리에서 지우지 못해,
   나중에 파일을 삭제해도 모든 클론이 영구히 그만큼 무거워진다.
2. **고객 제공 원본이거나 개인정보가 섞여 있다.** 저장소는 사내 전체가 클론한다.
3. **나만 쓰는 중간 산출물이다.** 공유할 이유가 없으면 공유하지 않는다.

## 왜 루트인가

`apps/` 나 `packages/` 밑에 두면 세 군데가 자동으로 집어간다.

1. **pnpm 워크스페이스**: `pnpm-workspace.yaml` 의 글롭에 걸려 `build`, `test`, `typecheck` 대상이 된다.
2. **배포 트리거**: `.github/workflows/deploy-{prod,staging}.yml` 의 paths-filter 가 `apps/**`,
   `packages/**` 를 감시한다. csv 하나 추가한 커밋으로 web 스택 전체가 `--no-cache` 재빌드된다.
3. **가드 스크립트**: `scripts/check-*.mjs` 가 앱 규약을 강제한다.

루트 `reference/` 는 셋 다 경로를 명시적으로 지정하고 있어 걸리지 않는다. `sandbox/` 를 루트에 둔
근거와 같다([sandbox/README.md](../sandbox/README.md) 참고).

## 파일 이름

날짜와 출처를 이름에 남긴다. 몇 달 뒤에 이 파일이 무엇이었는지 알 방법이 그것뿐이다.

```
data/2026-08-18_naver-datalab-화장품-일간.csv
images/2026-08-14_조직도-트리-시안.png
local/2026-08-10_고객제공-품목마스터-원본.xlsx
```
