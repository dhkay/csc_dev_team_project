# 02. 화면/페이지 구성

**상위 원칙**: 화면 흐름 자체는 특허 단계(S10~S60) + 검수/확정 절차를 따른다(00_개요.md,
08_개발인계/07_용어집.md "특허 단계 S10~S60" 참고). 아래는 그 흐름을 그룹웨어 화면으로
번역한 것이고, 실제 화면 개수(21개)·기능번호(F-01~F-102)는 `07_기능정의서/` PDF가 원본이다.

**공통**
- 경로: 그룹웨어 사이드바의 "RBFR 연구" 메뉴 진입
- **탭 배치**: 좌측 정렬로 [정방향 계산] [역방향 추천] [원료 등록/검증] 3개, **우측 정렬로 별도
  분리해 [설정] 탭 1개** (추가 — 아래 "설정(Profile 관리)" 참고). 우측에 따로 두는 이유는 앞의
  3개가 "매일 쓰는 작업 화면"인 반면 설정은 "구성 자체를 바꾸는 화면"이라 성격이 달라서다.
- **권한**: 그룹웨어 기존 계정/조직 체계 재사용 + 실제 시스템의 5단계 사용자 권한을 그대로
  가져온다 (`08_개발인계/07_용어집.md` "사용자 권한 5가지" 참고).

| 권한 | 할 수 있는 것 |
|---|---|
| ADMIN | 사용자·권한, **설정(Profile·역할 도메인·Cell 규칙 승인)**, 전체 조회 |
| REVIEWER | 검수 요청 처리(승인·수정요청·반려). 자기 처방은 자기가 못 함 |
| DESIGNER | 처방 생성·설계·산출·검수 요청 |
| DATA | 원료 등록·수정, 기여도·물성·단가, 규제 확정 |
| VIEWER | 확정된 처방 조회, 결과 문서 내려받기 |

  `FeatureKey`(`RBFR`) 자체는 그대로 유지하되, 그 안에서 위 5개 권한으로 다시 나뉜다. 한 사람이
  여러 권한을 가질 수 있다.

**역할 도메인 이름 주의**: 아래 각 탭 설명에서 "진정/정화/수분/보호/균형"으로 쓴 부분은
이전 설계 당시 붙인 임시 이름이다. 실제 스킨 Profile 잠정값은 **보습·진정·보호·정돈·균형**
(균형만 통합 역할)이다. 이름·순서는 확정 전이라 화면 문구는 반드시 `role_domains` 테이블 값을
그대로 읽어서 표시하고, 코드에 이름을 박지 않는다(05_스코어링엔진.md 참고).

**탭 1. 정방향 계산 (원료 → 결과, S50에 해당)**
- 입력: 원료 다중 검색·선택 + 각 원료 배합비율(%) 입력 — 배합비율(%) 합계가 100%를 초과하면
  저장/계산 버튼을 막고 즉시 경고 표시. 100% 미만은 계산은 허용하되 "잔여 배합비율 OO%가
  비어있음"을 안내 문구로만 표시.
- 출력: 역할 도메인 오각형 차트 — 원료/비율 변경 시 자연스럽게 애니메이션 전환(아래 "오각형
  차트 애니메이션 사양" 참고). **단, 이건 화면 프리뷰용이고 승인·확정에 쓰이는 공식 값은 반드시
  Cell 변환을 거친다**(05_스코어링엔진.md "Cell·오각형" 참고).
- 출력: 각 원료의 규제 등급 배지(ALLOW/LIMIT/BAN/**NODATA**) — NODATA를 "사용가능"과 다른
  모양으로 반드시 구분(04_식약청API연동.md, 05번 원칙4 참고).
- 출력: LLM 해석 텍스트.
- 출력: **직접 역할 4개**는 효능값+비중값을 표시. **통합 역할(균형)**은 독립 근거가 없으면 "미입력"
  으로 표시하고 0이나 평균으로 자동 채우지 않는다(05번 참고, 이전 설계 정정).
- 출력: 처방 검증 결과 — 배합비/사용량한도/pH/병용금기(BLOCK 시 확정 자체를 막음, WARN 시
  경고만)/조합계수/HLB/사용감·안정성/원가.
- 입력: 처방 저장(S50 산출 결과를 `formulas`/`formula_ratios`/`formula_ingredients`로 저장,
  상태는 `DRAFT`에서 시작).

**탭 2. 역방향 추천 (목표 → 원료, S40~S50에 해당)**
- 입력: 역할 도메인 슬라이더로 목표 비중(%) 입력, 합 100% — 슬라이더 조작 중에도 오각형이
  실시간으로 자연스럽게 이동.
- 출력: 추천 원료 후보 리스트(상위 N개, 근접도 순). 초기 버전은 단일 원료 추천, 여러 원료
  조합 탐색은 고도화 버전(추후).
- 출력: 각 후보에 LLM 설명.
- 규제 BAN/병용금기 BLOCK 원료는 추천 후보에서 자동 제외. NODATA 원료는 제외하되 "미확인이라
  제외됨"이라고 표시(허용 안 된 것처럼 조용히 빼지 않음).

**탭 3. 원료 등록/검증 (S20에 해당, DATA 권한)**
- 원료 기본정보 입력 폼 + "성분사전 조회" 버튼 — 04번 문서의 실제 MFDS API로 한글명 검색 시
  영문명(INCI)·CAS·기원·이명을 자동 채움(F-90). 사전에 없으면 직접 입력, "표시명칭 미확인"으로
  표시.
- 국가별 규제 확인 섹션 — 10개국 카드(KR/CN/US/CA/EU/JP/UK/RU/TW/ASEAN), 상태는 ALLOW/LIMIT/
  BAN/**NODATA** 4가지, 확정상태는 CONFIRMED/PROPOSED/REJECTED 3가지. AI가 찾아온 값은
  PROPOSED로만 표시되고 산출·검증에는 안 쓰인다(06번 참고).
- 인증 정보 섹션 — 비건/유기농/NMPA/저자극 4종. 인증기관·인증서번호·문서위치·**유효기간**
  입력, 유효기간 지나면 경고. 증빙 없이 넣은 값은 근거로 인정 안 함(03번 `ingredient_certs`).
- 무첨가 분류 — 파라벤류/페녹시에탄올/PEG류/BHT·BHA/실리콘류 중 해당 시 선택(법적 규제와
  별개 축, 클린뷰티 마케팅상 배제 대상).
- 물성 입력 — pH 범위, 용해성, 비중, HLB(유화제인 경우), 권장/절대 사용량 범위.
- 역할 기여도(직접 역할 4개) 입력 폼 — **각 역할 값은 +/- 스테퍼 버튼으로 증감**. 통합 역할
  (균형)은 이 폼에 없다 — 원료 단위가 아니라 처방 단위로만 별도 근거 입력(05번 참고).
- 원료 텍스처 지표(사용감 14항목 중 이 원료가 주는 영향, 0~1) — 예측 계산용.
- 근거유형·신뢰도·근거자료 첨부 입력.
- 검증 상태 뱃지(미검증/검증중/승인/반려) 및 담당 연구원 지정.

**탭3 부속: 원료쌍 조합 계수 입력**
- 원료 A/B 선택, 영향 역할, 관계(synergy/conflict/neutral/unknown), 계수(기본 1.0),
  신뢰도(low/medium/high), 근거출처(manual_estimate/lab_test/literature/expert_review/unknown).
- 이 화면도 lab_test가 아니면 반드시 "예측값" 배지를 달고 저장한다.

**탭3 부속: 원료쌍 병용 금기 입력 (추가, 반영 누락분)**
- 위 조합 계수(정도가 있는 시너지/충돌 계수)와는 별개로, **아예 같이 쓰면 안 되는 조합**을
  BLOCK/WARN 등급으로 등록하는 화면. BLOCK은 그 조합이 들어간 처방의 확정을 막는다(경고만이
  아님). `ingredient_incompat`(03번) 참고.

**처방 사용감·안정성 기록 (탭1에서 저장한 처방에 연결)**
- 사용감(끈적임/산뜻함/흡수감/발림성/잔여감/점도 등 14항목 중 관련 항목)과 안정성(분리/침전/
  변색/변취 위험, pH/열/저온 안정성) 실측 결과 기록. 계산이 아니라 실험/관능평가 기록이며,
  lab_test가 아니면 예측값 배지.

## 설정 (Profile 관리, 관리자 전용, 추가)

**우측 정렬 탭으로 분리, ADMIN 권한만 진입 가능.**

- 이 화면은 "지금 쓰는 5개 역할 도메인을 자유롭게 편집"하는 화면이 **아니다.** 스킨(Skin)
  Profile의 역할 구성(4직접+1통합, 잠정 이름 보습/진정/보호/정돈/균형)은 **특허 청구항에 묶인
  확정 구조**라 이 화면에서 수정할 수 없게 잠근다.
- 대신 이 화면이 하는 일:
  1. **Profile 목록 표시**: 스킨(사용 중)/클렌즈/배스/유기농/시그니처 중 활성화된 것만 사이드
     탭에 노출, 비활성 Profile은 화면에도 산출에도 안 낀다.
  2. **새 Profile 등록** — ADMIN만: Profile 이름, 역할 개수, 각 역할이 직접/통합 중 무엇인지,
     역할 이름과 순서를 등록. 저장하면 그 Profile 전용 오각형 각도(360°/역할수)와 Cell 판정
     기준선(역할수×3칸)이 자동으로 다시 계산된다 — **각도·기준선 재계산은 코드가 하지만, 그
     결과로 만들어진 Cell 규칙 판은 반드시 별도 승인을 받아야 한다**(아래 3번).
  3. **Cell 규칙 판 승인** — 비중(%)→칸수 변환표, 총 Cell 허용 범위를 화면에서 설정하고 ADMIN이
     승인. 승인된 판은 화면에서 다시 못 고치고, 바꾸려면 새 판을 만든다(05번 "Cell·오각형" 참고,
     승인자·승인일자 기록).
  4. Profile을 새로 켜거나 역할 도메인을 바꾼 뒤에는 기존 처방의 역할 줄을 맞추는 절차가
     필요하다(원본 시스템의 `migrate.php roles`에 해당 — 그룹웨어에서는 관리자 액션 버튼으로
     제공, 확정된 처방은 건드리지 않음).

## 오각형 차트 애니메이션 사양

역할 도메인 오각형(또는 N각형, Profile마다 역할 수가 다르면 각도도 달라짐)은 값이 바뀔 때
자연스럽게 애니메이션 전환된다. **이건 화면 프리뷰 레이어이고, 승인·확정용 공식 표현은 05번의
이산 Cell 변환을 거친다** — 둘을 혼동하지 않는다.

- **트리거**: 탭1 — 원료 추가/삭제, 배합비율(%) 변경. 탭2 — 슬라이더 드래그.
- **동작 방식**: 축마다 독립적으로 보간(tween)하여 유기적으로 움직임.
- **타이밍**: 250~400ms, ease-out 계열. 연속 입력 시 진행 중인 전환 위에 새 목표값을 덮어써서
  끊김 없이 이어지게 함.
- **구현 기술**: `svelte/motion`의 `tweened` 또는 `spring`.
- **확인 필요**: 스프링형 vs 트윈형 최종 느낌은 프로토타입 확인 후 확정.
