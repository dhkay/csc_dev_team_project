## 3. 성분 DB 구조 — 우리 스키마에 직접 반영할 것

### 목록 화면 컬럼

`INCI NAME` · `한글명` · `CAS NO` · `EWG` · `기능` · `사용범위(%)` · 상세
필터: **금지물질 포함** 여부

- **CAS NO가 복수**입니다. 예 Dimethicone → `141-62-8 / 141-63-9 / 63148-62-9 / 9006-65-9 / 9016-00-6`
- **기능**은 화장품 배합목적 분류입니다. 우리 역할 도메인과 별개 개념 →
  `피부보호제` `피부컨디셔닝제(유연제)` `기포방지제` `유화안정제` `점증제-수용성` `계면활성제-세정제` `보존제` `자외선차단제` 등

### 상세 모달 — 탭 5개

`기본정보` · `규제` · `물성` · `협력사 자료` · `카테고리영향`

#### 규제

10개국을 카드로 표시합니다. **KR · EU · US · JP · CN · ASEAN · RU · TW · UK · CA**

- 국가별 상태를 `사용 가능` / `규제 정보 없음` 으로 **구분해서** 보여줍니다.
  → **「허용」과 「데이터 없음」을 절대 같게 처리하면 안 됩니다.** 우리 설계에 반드시 반영.
- 하단에 **독성·우려물질 지표** 별도 섹션. 예 `Prop 65 (캘리포니아 OEHHA) — 없음, 목록 대조완료`
  → 상품기획팀이 준 검토 사이트 목록의 OEHHA와 연결됩니다.

## 4. 우리가 놓치고 있던 것 — 반영 필요

### 반드시 넣어야 할 것

| 항목 | 이유 |
|---|---|
| **비호환 원료 (병용 금기)** | 성분끼리 같이 못 쓰는 조합이 있습니다. 검증 단계에서 잡아야 실무에서 씁니다. 성분 자기참조 다대다 |
| **「규제 정보 없음」 상태 구분** | 허용과 미확인을 구분하지 않으면 잘못된 안전 판단을 유도합니다 |
| **EWG 등급** | 우리 인증 조건에 `저자극(EWG 1-2)`이 있는데 실제 EWG 데이터가 없어 판정이 불가능합니다 |
| **용해성 · pH 범위 · 비중** | 배합 산출과 상 구분에 필요한 최소 물성입니다 |
| **기능(배합목적) 분류** | 업계 표준 분류입니다. 이걸 갖고 있으면 역할 기여도를 추정하는 근거가 됩니다 |
| **CAS 복수 대응** | 단일 컬럼으로는 담기지 않습니다 |

### 텍스처 효과 — 설계 관점의 발견

우리는 사용감 14개를 **프로젝트 조건으로만** 받고 산출에는 쓰지 못합니다.
코칭클럽은 **성분마다 텍스처 지표를 0~1 수치로** 갖고 있어서, 「실키하게」 같은 조건을 실제 배합 산출에 반영할 수 있습니다.

→ 성분 등록 항목에 텍스처 지표를 넣으면 우리 F-21(사용감 선택)이 비로소 산출에 연결됩니다.

### 참고할 만하지만 우리 범위 밖

| 기능 | 판단 |
|---|---|
| 완제품 36만건 역분석 벤치마크 | 완제품 DB가 없어 불가. 장기 과제 |
| 생산 관리 (생산지시·재고·일탈) | ERP 영역. RBFR 범위 밖 |
| HLB 계산기 | 유화 설계 보조. 물성에 HLB를 담으면 나중에 붙일 수 있음 |
| 검수함 (크루 리뷰) | 우리 권한 설계에 「검수」 단계를 넣을지 검토 가치 있음 |
| 처방명만 입력 → 자동 설계 | 접근이 반대입니다. 우리는 역할 비중에서 출발 |

## 5. 접근 방식의 차이

| | 코칭클럽 | RBFR |
|---|---|---|
| 출발점 | 처방명 · 완제품 벤치마크 | **역할 비중** |
| 근거 | 150만 건 데이터 교차 질의 | **특허 기반 설계 방법론** |
| 산출물 | 배합비 · 공정 · 검증 리포트 | 배합비 + **RBDR 외부 표현(오각형)** |
| 데이터 | 범용 공개·수집 데이터 | **자사 연구소 기준값** |
| 외부 연결 | 규제 검증 리포트 | RBDR 브랜드 표현까지 |

**우리 강점은 자사 기준의 일관성과 외부 표현까지 이어지는 체계**입니다.
데이터 양으로 경쟁하는 방향은 승산이 없습니다.
